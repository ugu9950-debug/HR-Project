채용파트 주간 리포트를 엑셀에서 생성합니다.

## 실행

작업 폴더는 `c:\Users\user\Desktop\채용파트_주간리포트` 입니다.

```
node build-report.js $ARGUMENTS
```

- 인자가 없으면 폴더에서 **가장 최근 수정된 .xlsx** 를 자동 선택합니다 (Excel 임시파일 `~$...` 는 제외).
- 특정 파일을 쓰려면 파일명을 인자로 넘깁니다: `node build-report.js "채용 실적,예정 사항_260904.xlsx"`
- 출력 파일명은 금주 금요일 날짜로 자동 결정됩니다: `YYYY-MM-DD_채용파트_주간리포트.html`

## 실행 후 할 일

1. 콘솔 요약(기간 · 금주/차주 건수 · 본부 분포 · 최종합격 수)을 사용자에게 그대로 보고한다.
2. `⚠ 확인 필요` 경고가 출력되면 **반드시** 해당 엑셀 행 번호와 함께 사용자에게 알린다.
   본부·진행내용 누락, Report 출력이 금주/차주가 아니라 제외된 행 등이 여기 잡힌다.
3. 생성된 HTML 경로를 알려주고, 브라우저로 열어 확인할지 물어본다.
4. 사용자가 시각 확인을 원하면 헤드리스 크롬으로 스크린샷을 떠서 보여준다:
   ```
   "/c/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --disable-gpu \
     --hide-scrollbars --screenshot=<경로>.png --window-size=800,4600 \
     --user-data-dir=<스크래치패드>/cdp "file:///<리포트 절대경로>"
   ```

## 리포트 규칙 (사용자와 확정된 사항)

- **면접 단계별 그룹** (2026-09-04 변경) — 금주·차주 모두 `1차 면접` / `2차 면접` 카드로 묶는다.
  카드 안은 면접일 → 본부 순서 → 팀명 순 정렬. 그 이전의 본부별 카드 구성은 폐기됨.
- **팀명 우선 표기** (2026-09-04 변경) — 항목 첫 줄은 **팀명(채용 부서)**, 둘째 줄이 포지션명.
  카드가 단계를 나타내므로 단계 배지는 빼고, 그 자리에 **본부 배지**를 둔다.
  본부 색상·정렬 순서는 고정: E-biz → FS상품기획 → FS운영 → TT운영 → TT상품기획 → 소싱 → 경영지원.
- **본부명 표기 통일** — 엑셀에 `E-biz`/`E-BIZ본부` 가 섞여 들어오므로 후행 "본부"를 떼고 통일한다.
  그래도 `HQ_ORDER` 에 매칭되지 않는 이름은 경고로 알린다. 오타면 엑셀을 고치고,
  실제로 새 본부면 `HQ_ORDER`·`HQ_COLOR` 에 등록한다 (2026-09-04 `FS운영` 추가).
- **요약형 2열** — 팀명/포지션 · 배지 / 날짜·면접관 / 결과·사후조치 3줄 구성.
- **채용 특이사항은 금주만** (2026-09-04) — 특이사항 시트에서 `Report 출력` 이 `금주` 인 행만 싣는다.
  지난주 행은 `-` 로 남아 있으므로 비어 있지 않다고 다 실으면 안 된다.
- **최종합격 판정** — 엑셀은 "최종합격" 을 진행내용이 아니라 **사후조치**에 적는 경우가 많다
  (진행내용 "1명 진행완료, 합격" / 사후조치 "최종합격, 처우협의 中"). 두 열을 함께 보되 1차·불합격은 제외.
- **온보딩 배지** — `입사 준비` 값을 그대로 표기한다(`입사 완료`/`준비 완료`/`준비 중`). 색만 상태로 구분.
  이미 입사한 인원을 "입사예정" 으로 세지 말 것 — 섹션 제목은 `금주 입사 N명 · 입사예정 N명`.
- **KPI 타일** — 세 번째 타일은 `중도 이탈/면접 취소 등`, 부제는 본부 + 구분으로 집계한다
  (예: `E-biz 면접취소 1건`).
- **실명 전부 표기** — 면접관, 최종합격자, 중도이탈 후보자 모두 엑셀 그대로 노출한다. 익명화하지 않는다.
  (※ 이 리포트는 사내 메일용이며, Vercel 배포 산출물의 개인정보 규칙과는 별개다.)
- **디자인** — Pretendard, 벤토 그리드 카드, 본부별 액센트 컬러, 로드 시 순차 페이드업.
- **요청 대비 수행 현황** (시트 "6.1 이후 요청 대비 수행") — 차주 예정사항 뒤, 채용 특이사항 앞에 배치.
  요청 건수는 **문서번호 고유값** 기준(행 수 아님 — 한 요청서에 복수 인원이 있고 중복 행도 있다).
  잔여 단계는 **건 기준**, 완료율은 **인원 기준**이다. 두 기준이 섞여 보이지 않게 라벨을 명확히 유지할 것.
  착수율은 대기중이 없으면 100%이며, 취소·보류는 착수한 것으로 본다.

## 수정 요청 처리

| 요청 | 고칠 곳 |
|---|---|
| 데이터가 틀렸다 | **엑셀을 고치고 다시 생성**한다. HTML을 직접 손대지 않는다. |
| 색상·여백·폰트·카드 모양 | `build-report.js` → `4. 디자인 토큰 & 렌더링` |
| 본부 순서·팔레트 | `build-report.js` → `HQ_ORDER`, `HQ_COLOR`, `hqCanon` |
| 단계 카드 색상·순서 | `build-report.js` → `STAGE_ACCENT`, `STAGE_ORDER` |
| KPI 타일 항목 | `build-report.js` → `main()` 의 `kpi` 객체 |
| 요청 대비 수행 계산 방식 | `build-report.js` → `main()` 의 "요청 대비 수행 (누적)" 블록 |
| 엑셀 열/시트 구조가 바뀜 | `build-report.js` → `2. 시트 → 레코드`, `main()` 의 `field(...)` 호출 |

## 주의

- 엑셀이 Excel에서 열려 있어도 읽힌다. 저장하지 않은 변경분은 반영되지 않으니, 최신 내용이 안 보이면 사용자에게 **엑셀 저장(Ctrl+S)** 을 먼저 요청한다.
- 메일 본문 크기가 95KB를 넘으면 스크립트가 경고한다. Gmail은 102KB에서 본문을 잘라낸다.
- 외부 패키지 의존 없음(zip/XML 파서 내장). `npm install` 불필요.
